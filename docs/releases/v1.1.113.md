# Knot 1.1.113

## Highlights

- Linux share audio survives a PipeWire system that cannot build the muted
  loopback return. Capture now starts anyway instead of leaving the share
  carrying digital silence while reporting itself healthy, and the status line
  says your speakers are silent while sharing instead of leaving you to think
  the share muted your machine. The PCM mute failsafe is also released as soon
  as routing is live, so a slow `pactl` round trip can no longer mute a
  working share.
- A share tile that falls back from native AV1 no longer renders black. A dead
  hardware decoder painted solid black while still counting frames, so the
  recovery path skipped it; a black picture now retries software decode, and an
  orphaned native canvas is dropped when no live player owns it.
- Liveness sampling is throttled to 250 ms. The per-frame `getImageData`
  readback was stalling the renderer on every painted 4K frame, so a healthy
  share ran behind.
- A share tile reveals on a poll floor under `requestVideoFrameCallback`, which
  only fires for a *new* frame and so never fired for a stalled or pre-decoded
  stream. A removed tile clears its timer instead of leaking one.
- On Wayland, the display you pick in the portal is the display that is shared
  instead of the first one the desktop capturer reports.
- Only `argv[0]` decides whether a process is Knot's own playback. Matching
  "knot" anywhere on the command line pulled unrelated apps onto the share
  sink, so their audio never reached the share.
