# Knot 1.1.128

Screen shares and calls from 1.1.127 still work with this version in both
directions; nothing about how they travel changed.

## Screen sharing: less lag

- **A 4K share no longer falls behind on the CPU.** Knot's software decoder ran
  in a mode that used very few CPU threads: about 49 pictures a second at 4K,
  15 at a high bitrate, so a 4K60 share fell behind and "only 12 fps shown"
  was a common sight. It now starts in a mode that keeps up with 4K60, and
  switches between its two modes by itself: low delay for a quiet screen, full
  speed for a busy one. A screen that stops changing still shows its last
  change at once.
- **The picture plays 160 ms behind the newest one (it was 250 ms), and the sound
  follows.** If your connection needs more, it still grows and comes back down.
- **A quiet screen can no longer get stuck.** Pictures far apart (a mostly still
  desktop) could leave the player waiting for a picture it never asked for.
- **The fast UDP connection no longer waits on a slow name lookup.** One lost DNS
  packet made the system wait 5 seconds before Knot even tried the fast
  connection, so about one share in three started on the slower route. Names are
  looked up in parallel with a short retry, remembered, and looked up ahead of
  time. Fast file transfers start sooner for the same reason. The UDP
  connection also asks for larger buffers.
- **"On GPU" is only said when it is true.** The line under a friend's share said
  GPU whenever a hardware decoder had been asked for; it now says GPU only when
  your computer really decodes that codec on its GPU.

## AV1 on your NVIDIA GPU (Linux)

- Chromium cannot show the pictures its own NVIDIA decoder makes on Linux (they
  arrive black), so AV1 shares used the CPU. Knot now carries its own small
  decoder that runs NVIDIA's NVDEC directly, scales each picture on the GPU to
  the size it is shown at, and hands it over the moment it is decoded. It is
  used for windows up to 2560x1440; full screen on a 4K display still decodes
  on the CPU, because a full 4K picture is too much to copy between programs.
- Every picture's first frame is checked against a software decode, and a GPU
  decoder that fails, goes quiet or shows a different picture is replaced by the
  CPU decoder for the rest of the share.
- **Settings → Screen sharing → Decode shared screens on the NVIDIA GPU** turns it
  off. It applies from the next share.

## Bitrate

- **A 4K60 share now starts at 30 Mbps (it was 16)**, and other sizes scale from
  it. The number is the same whoever is watching: it used to climb toward the
  whole connection whenever the viewer's GPU could decode AV1, which made the
  rate depend on who watched.
- **A number you choose on the slider is the number used**, held only to what your
  connection, your friend's and the encoder can carry. It used to be cut to the
  automatic value. The slider shows 30 until you move it.

## Sound (Linux)

- **You hear your own shared sound about 40 ms behind instead of about 150 ms.**
  While you share your computer's sound, your speakers now play it through
  PipeWire directly, faded up from silence once Knot has checked it is on your
  speakers, instead of through Knot's capture path (late and softened). Each
  share's return has a name nothing has remembered, because PipeWire restores a
  stream's old volume by name. If it ever fails or disappears, Knot plays the
  sound itself again. **Settings → Screen sharing → Hear your own shared sound at
  low delay** turns it off.
- A sound route that fails while it is being set up now removes the private sink
  it had created instead of leaving it behind.

## Behind the scenes

- Tests no longer open windows on the screen of the person running them; they
  run without a display. (Linux ignores window transparency, so the "invisible"
  windows were ordinary ones that took the keyboard focus.)
- A new test fails the build if a file the app loads at startup is missing from
  the package.
