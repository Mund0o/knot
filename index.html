    Privacy & security

    Your directory host stores account, friend, server, group-membership, channel, presence, and encrypted offline-envelope metadata. Message contents are encrypted on your device; encrypted SQLite chat history stays on your devices.

    Calls and screen shares stay direct P2P. Files prefer direct TCP/WebRTC; only your explicit encrypted object-relay opt-in can use short-lived presigned storage, and the Worker never proxies file bytes. Offline text is stored only as encrypted envelopes until acknowledged.

    File transfers

    Auto tries an authenticated direct TCP lane first, then falls back to the direct encrypted WebRTC connection.

    1. Open the same direct message as your friend.
    2. Wait until Knot says Connected directly.
    3. For TCP, forward the selected port and allow Knot through your firewall.
    4. Send a small test file first; Auto falls back safely if TCP is unreachable.

    Troubleshooting
    • Using WebRTC fallback: TCP could not reach your friend. Check the router rule, firewall, and port.
    • TCP-only failed: use Auto or WebRTC-only unless at least one person has a reachable forwarded port.
    • Encrypted object relay: this explicitly labeled last resort is capped at 64 MB and only appears when the host confirms automatic deletion.
    • Transfer stalled or failed: retry once after both people reopen the chat. The sender’s upload speed and receiver’s disk speed set the maximum speed.
    • Transfer cancelled: either person can cancel; use Retry to start a fresh transfer.
